# Touchline FC 3D 1.7.0 개선·검증 기록

게이지가 가득 차는 시간은 0.92초에서 0.78초로, 공 지름은 23cm에서 32.2cm로 바뀌었습니다. 경기 능력치 85·체력 100%·공 없이 달리기의 최고 속도는 양 팀 모두 9.09m/s에서 7.66m/s로 줄었습니다. 달리거나 멈출 때 속도가 점진적으로 변하고, 턴 각도가 커질수록 감속이 커집니다.

빠르게 꺾으면 바깥발이 잔디를 짚고 무게중심이 낮아집니다. 고관절·무릎·발목을 따로 움직여 정강이와 축구화가 따라가도록 했습니다. 원거리 모델에도 같은 관절 구조를 적용했습니다. LAN 대전과 골 리플레이에도 속도, 발 디딘 위치와 시간을 전달합니다. 온라인은 양쪽 모두 1.7.0(프로토콜 7)을 사용합니다.

EA Korea의 큰 각도 드리블 턴 안내에서 양발로 턴하고 후속 동작으로 연결하는 흐름을 참고했습니다. 충전 시간, 크기, 속도와 발 디딤 시간은 이 게임에서 조정한 값입니다.

재현 도구는 tools/check_pass_reception.py입니다. 키와 렌더러를 함께 사용하는 tools/record_kick_demo.py로 짧은 패스, 긴 패스, 자동 수신과 슈팅을 검증할 수 있습니다. LAN 대전은 양쪽 모두 1.6.0(프로토콜 6)을 사용합니다.

- 실제 렌더러의 28가지 세트피스 카메라·홈 복귀 검사: 양 팀·전후반·양쪽 측면을 점검했습니다.
- 화면 통합 검사: 7개 시즌 카드, 선수 검색, 단계별 팩 공개와 중복 결제/지급 방지, 관절 축, 4종 개인기 입력, 휘슬 1회, 4종 세레머니, 기록 기반 리플레이·건너뛰기·홈 복귀를 점검했습니다.
- Windows x64 교차 빌드와 최종 동결 실행본 검사 결과는 VERIFICATION.txt에 기록합니다. Windows 실제 PC 실행·스피커 출력은 이 환경에서 검증하지 못했습니다.

## 성능

같은 Linux llvmpipe·1280×720·LOW·150프레임·동일 입력으로 1.4.0과 최종 1.5.0을 순차 측정했습니다. 물리, HUD/장면, 렌더링 및 프레임버퍼 읽기를 포함합니다.

| 프레임 처리시간 | 1.4.0 | 1.5.0 |
| --- | ---: | ---: |
| 중앙값 | 8.936ms | 8.925ms |
| 95백분위 | 11.138ms | 10.614ms |

거리 모델을 추가하기 전에는 새로운 상세 모델 때문에 처리 비용이 증가했습니다. 기본 성능 우선에서는 멀리 있는 선수 메시를 간소화하고 선택 선수·근거리 외형을 유지해 부담을 줄였습니다. 이는 특정 테스트 환경의 처리 비용이며 Windows 실제 FPS 보장이나 온라인 지연 측정은 아닙니다. 원자료는 validation/benchmark_v140.json 및 benchmark_v150_final.json에 있습니다.

## 외형·사진·남은 범위

사진 134명은 PHOTO_CREDITS.md에 개별 출처·저작자·CC/퍼블릭 도메인 조건을 기록했습니다. 원본 섬네일 파일은 수정하지 않았으며, 게임에서 UV 프레이밍과 간이 얼굴 표면 투영을 사용합니다. 카드 사진이 모두 해당 시즌 당시에 촬영된 것은 아닙니다. 출처 사진이 없는 선수는 자체 모델 초상입니다. 정밀 3D 스캔, 전문 모션 캡처, 원작과 동일한 얼굴 품질은 구현하지 못했습니다.

골 리플레이는 경기 데이터를 재생하는 기능이며 전체 경기 동영상 녹화·저장은 아닙니다. 오프사이드·경고/퇴장·승부차기·전체 개인기·공개 매칭 서버는 없습니다. 온라인은 직접 TCP 연결이며 양쪽 모두 1.5.0(프로토콜 5)을 사용해야 합니다.
